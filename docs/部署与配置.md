# 部署、配置与数据维护

## 环境变量

复制根目录 `.env.example` 为 `.env`，不提交真实配置。npm workspace 脚本在 apps/api 下运行时，后端会查找根 `.env`。

| 配置                 | 作用                                                  |
| -------------------- | ----------------------------------------------------- |
| NODE_ENV、DEV_AUTH   | 非 production 且 DEV_AUTH=true 才有体验登录           |
| ADMIN_PASSWORD       | 至少 12 位，启用管理登录；无默认密码                  |
| HOST、PORT           | API 监听地址 / 端口；本机默认 127.0.0.1:3100          |
| COOKIE_SECURE        | HTTPS 正式部署设为 true                               |
| DATA_DRIVER          | file（默认）或 postgres                               |
| DATA_DIR、UPLOAD_DIR | 本地状态、原图片与缩略图持久化目录                    |
| DATABASE_URL         | PostgreSQL 连接串，仅后端使用                         |
| WEATHER_PROVIDER     | disabled（默认）或 qweather                           |
| QWEATHER_HOST        | 开发者控制台分配的 `*.qweatherapi.com` 域名，不带协议 |
| QWEATHER_API_KEY     | 天气 API Key，仅后端使用                              |

`.env` 修改后重启 API。地图和天气统一从 [管理工作台 → 系统配置](http://127.0.0.1:5173/admin?tab=system) 管理。首页右上角齿轮可直达；尚未设置管理密码时页面会提示初始化方法。

高德 JS Key、JS 安全码和热度阈值保存后刷新页面重新初始化地图。天气服务、API Host、API Key 可直接在下方“气象服务配置”表单填写，保存后立即生效，不需重启。密钥留空保留，勾选清除后删除；启用天气必须同时配置域名和密钥。测试按钮使用贵阳公共参考坐标，不读取设备位置。

天气密钥采用 AES-256-GCM 加密，后台与公共 API 均不回显原文，审计不记录密钥。加密主密钥首次保存时写入 `DATA_DIR/.config.key`。必须和数据一起备份，丢失后需重新配置天气密钥；PostgreSQL 部署也要保留 app 的数据卷。后台配置优先于环境变量，尚未保存后台配置时才使用环境变量。对象存储密钥配置或短信 OAuth 控制台仍为后续项。

## Docker 启动

```powershell
docker compose up -d --build app
docker compose logs -f app
```

HTTP 本地开发保留 COOKIE_SECURE=false，否则浏览器不会在 HTTP 请求携带 Secure Cookie。公开部署先配 HTTPS 反向代理，再打开 Secure；反向代理应保留 Host / Origin，不要把所有来源改成可信来源。生产模式禁用开发身份，需接入真实认证后才可让普通钓友长期使用。

Compose 的 named volumes 分别保管数据、上传、数据库；升级镜像不删除这些卷。数据库备份与图片备份需要同时考虑，卷不是备份。不要使用带 `-v` 的销毁命令清理业务数据。

## 后配 PostgreSQL

1. 在 `.env` 设置强 `POSTGRES_PASSWORD`。
2. 启动 `docker compose --profile database up -d db`，等待 healthcheck 正常。
3. 本机 Node 连接：`DATABASE_URL=postgresql://fishing:你的密码@127.0.0.1:5432/fishing`。
4. Docker app 连接同一 Compose 数据库：主机改为 `db`，端口仍为 5432。
5. 将 `DATA_DRIVER=postgres`，重启 API / app。

当前适配器首次连接自动建 `fishing_state` JSONB 状态表，没有导入演示数据。切换驱动不会自动搬迁 file 仓储内容，先备份；若已有真实记录，需要专门迁移并校验用户、素材编号和图片目录对应关系。当前尚未提供一键数据迁移工具。

数据库连接失败会阻止服务启动，而不是默默回退成另一份空文件数据。

## 后配高德与天气

高德：控制台创建 Web JS API 凭据并限制域名，后台填写 Key / 安全码，刷新 H5；水域维护坐标统一为 WGS84。页面会转换成高德展示坐标。贵州区域限制仍未启用，不会因填写 Key 自动变成已限制省内。

天气：管理工作台的“系统配置 → 气象服务配置”选择和风天气，填写控制台分配的域名和 API Key，保存后新提交自动调用；也支持环境变量作为初始配置。失败不阻塞素材保存。旧记录不使用后来天气冒充现场天气。适配器尚未完成真实账户联调，需配置后通过“测试已保存配置”验证额度、返回格式与服务端网络。

## 初始化运营顺序

1. 设置管理密码并登录。
2. 维护真实水域（名称、地区、WGS84 代表点），选填公开入口和提醒。
3. 确认活动起止时间、积分草案、任务目标、称号门槛和奖励说明，再启用计分。
4. 发布活动公告；开发体验不保留伪造名次。
5. 配置高德、天气与真实登录，完成真机验证。
6. 最后接入贵州边界校验，再验证省外 / 省界场景。

## 数据维护

- file 模式备份 `data/state.json` 与 `uploads/`，备份时停止写入或使用一致性快照。
- PostgreSQL 模式备份数据库与素材卷。
- 撤销是逻辑撤销，不物理删除个人照片。留存期限、用户彻底删除及对象存储清理为后续需求。
- 上传成功但未形成记录的孤立素材目前不会自动删除，需要后续定时清理策略。
- 管理台导出不含精确定位，不能替代数据库完整备份。

## 手机与浏览器

现场相机 / 定位需要安全上下文。电脑 `localhost` 可开发；手机访问电脑局域网 HTTP 地址不满足定位与现场拍摄条件。电脑热点联调流程：

1. 启动 API（`npm run dev -w @fishing/api`）。如需电脑页面，同时启动普通前端（`npm run dev -w @fishing/web`）。
2. 安装 OpenSSL，并运行 `npm run setup:mobile` 生成本地开发 CA、适用于热点地址 `192.168.137.1` 的服务端证书及 iPhone 描述文件。热点 IP 若有变化，可传参：`npm run setup:mobile -w @fishing/web -- 新的热点IPv4地址`。
3. 运行 `npm exec --workspace=@fishing/web -- vite --host 0.0.0.0 --port 5174 --strictPort`，提供 HTTP 证书下载页。运行 `npm run dev:mobile`，提供 HTTPS 页面。手机需连电脑热点；Windows 防火墙应允许私有网络访问 5174 和 5175。
4. 在 iPhone Safari 打开 `http://192.168.137.1:5174/gofishing-dev-ca.mobileconfig`，下载后进入“设置 → 已下载描述文件”安装。然后进入“设置 → 通用 → 关于本机 → 证书信任设置”，对 **GoFishing Local Dev CA** 开启完全信任。
5. 在 iPhone Safari 打开 `https://192.168.137.1:5175/`。确认地址栏是 HTTPS，再按网页提示允许位置和相机。iPhone“设置 → 隐私与安全性 → 定位服务”须开启定位，并在 Safari 网站设置中允许位置。

本地 CA 私钥保存在忽略提交的 `dev-certs/`，不要复制或提交；仅在自己的设备安装该描述文件，联调结束可从“设置 → 通用 → VPN 与设备管理”移除。服务端证书有效期为 90 天，过期后重新运行生成脚本即可；若重新生成了 CA，还需重新安装并信任 iPhone 描述文件。

需要真机验证微信、抖音内置浏览器以及 iOS / Android：授权拒绝、拍摄返回、软键盘、安全区、分享卡、下载和高德唤起。当前没有承诺全部容器已兼容。
