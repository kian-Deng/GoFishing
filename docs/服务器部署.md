# Linux 服务器部署（Docker + 域名）

采用 GitHub 拉取与独立发布时，请使用 [GitHub 发布流程](GitHub发布流程.md) 的命令；它会另外加载 `compose.release.yaml` 和版本镜像。下面的直接构建命令适用于首次手工部署，不能用于覆盖脚本管理的版本镜像。

此配置适合单台 Linux 服务器的小范围内测：Caddy 对外提供 HTTPS，应用容器处理 H5 与 API，状态和照片保存在 Docker 数据卷。当前生产模式尚无普通钓友的微信 / 手机号登录，不能作为正式公开运营版本；`DEV_AUTH` 在生产模式不会生效。

## 准备

- 域名 A / AAAA 记录指向服务器，公网 TCP 80、443 和 UDP 443 可到达服务器；如已有服务占用 80 / 443，需使用现有反向代理，不能同时启动本文件中的 Caddy。
- 服务器装有 Docker Engine 和 Docker Compose 插件，已把项目文件放在同一目录。
- 不要把本机 `.env`、`data/`、`uploads/`、`dev-certs/` 直接上传为容器镜像。若要迁移本机数据，另行备份状态文件、照片和 `DATA_DIR/.config.key`，核对后导入服务器数据卷。

## 配置与启动

在服务器项目根目录执行：

```bash
cp .env.server.example .env
chmod 600 .env
```

编辑 `.env`：把 `APP_DOMAIN` 改为真实域名，给 `ADMIN_PASSWORD` 设置至少 12 位的独立强密码。保持 `NODE_ENV=production`、`DEV_AUTH=false`、`COOKIE_SECURE=true`。不要把密码或 `.env` 提交到仓库。

```bash
docker compose -f compose.yaml -f compose.server.yaml config --quiet
docker compose -f compose.yaml -f compose.server.yaml up -d --build app caddy
docker compose -f compose.yaml -f compose.server.yaml ps
docker compose -f compose.yaml -f compose.server.yaml logs --tail=100 app caddy
curl -fsS "https://你的域名/api/health"
```

浏览器访问 `https://你的域名/`；管理入口是 `https://你的域名/admin?tab=system`。Caddy 通过域名自动申请和续期证书，证书数据保存在 `caddy-data` 卷。应用仍由原 Compose 绑定在服务器本机 `127.0.0.1:3100`，Caddy 在内部容器网络通过 `app:3100` 连接应用。

## 上线前检查

1. 手机 Safari 打开 HTTPS 地址并测试定位、现场相机和页面跳转。部署域名须加入高德 JS API 的域名白名单，再在管理台填写地图 Key 与安全码；天气后配。
2. 管理员录入真实水域。首次部署没有点亮数据；如想保留本机录入的水域和素材，需要迁移持久化数据，不能只复制镜像。
3. 定期备份 `fishing-data` 和 `fishing-uploads` 卷；天气密钥的解密主密钥也在数据卷中。卷持久化不等于离机备份。
4. 正式开放钓友注册与分享前，完成真实用户认证，并复核隐私、账号找回与运营规则。生产模式下体验账号已禁用。

如域名通过 CDN 代理、服务器已有 Nginx / Caddy、或使用云负载均衡，应改用现有 HTTPS 入口转发到本机 `127.0.0.1:3100`，保留原始 `Host` 和 `Origin` 请求头。
